# The PaperPull name

The PaperPull name and logo identify this project, the one at
github.com/rheeloaded/paperpull, and the releases published from it. The
code is free software under the AGPL. The name is not part of that grant.
The point is that when someone downloads something called PaperPull, it
is this project, read-only and reviewed, and not a copy with a payment
step added.

## What you can do without asking

- Use the name to refer to the project. "I archive my statements with
  PaperPull." "This works with PaperPull."
- Fork the repository on GitHub. GitHub forks keep the repository name and
  say where they came from, and that is fine.
- Distribute unmodified copies of a release, with the name, as long as you
  say which release and where it came from.
- Say that your project is built on, based on or compatible with PaperPull,
  as long as the wording makes clear it is yours and not this project.
- Package PaperPull for a Linux distribution or a package manager under the
  PaperPull name, provided the package is built from an unmodified release
  or from patches you send upstream.

## What needs a rename

- A modified version distributed to other people. Pick your own name and
  say it is derived from PaperPull. "Statement Fetcher, a fork of PaperPull"
  is fine. "PaperPull Pro" and "PaperPull for Business" are not.
- A hosted service that runs this code for other people, under any name
  that includes PaperPull.
- A domain name, app-store listing, package-index name, social account or
  company name that includes PaperPull. The project's own domain is
  paperpull.net.
- Anything that suggests the project endorses it.

## The one thing to remember

If people could reasonably think your thing came from this project, and
it did not, use a different name. If you are not sure, open an issue and
ask. Permission for reasonable uses is easy to get.
